# 模块设计：流量统计库与脱敏配置库

## 1. 职责与边界

- **负责的事**：
  1. 维护内存最近 36 秒实时上下行速率环形缓冲，提供毫秒级实时读取。
  2. 使用纯 Go 版 `SQLite`（`modernc.org/sqlite`）持久化各组织、各出口节点的上下行字节增量。
  3. 自动执行保留策略：仅保留最近 48 小时的分钟级细粒度采样，自动向上归并写入按小时（`traffic_hourly`）、按天（`traffic_daily`）、按月（`traffic_monthly`）聚合表，避免数据库体积无限膨胀。
  4. 提供按 `live | day | week | month30 | monthly` 五种粒度查询趋势序列、总流量（合计/下行/上行）及按组织、按出口节点的流量占比分布。
  5. 读写本机应用设置（`settings.json`），生成强制剥离所有 `ts-state` 私钥目录与本机鉴权令牌的脱敏配置 JSON。
- **不负责的事**：不直接连接 `sing-box` 进程，也不负责前端图表绘制。

## 2. 结构与数据流

### 2.1 目录与文件划分
- `internal/contract/types.go`：定义 `Organization`、`ExitNode`、`Rule`、`RuleProvider`、`LiveConnection`、`TrafficOverview`、`SystemSettings`、`SanitizedExport` 等全局结构体。
- `internal/stats/schema.go`：SQLite 建表语句与索引初始化（开启 WAL 模式）。
- `internal/stats/recorder.go`：内存 36 秒环形队列 + 流量增量写入与 48 小时过期细粒度清理。
- `internal/stats/query.go`：按 `live | day | week | month30 | monthly` 查询时间轴序列、总计 GB/字节数、组织占比数组与节点排行数组。
- `internal/configstore/store.go`：原子读写本机 JSON 状态文件（先写 `.tmp` 再 `Rename`）与导出 `SanitizedExport`。

### 2.2 SQLite 表结构
- `traffic_samples(bucket_minute INTEGER, org_id TEXT, node_id TEXT, down_bytes INTEGER, up_bytes INTEGER, PRIMARY KEY(bucket_minute, org_id, node_id))` —— 每次写入时顺带执行 `DELETE FROM traffic_samples WHERE bucket_minute < cutoff_48h`。
- `traffic_hourly(hour_key TEXT, org_id TEXT, node_id TEXT, down_bytes INTEGER, up_bytes INTEGER, PRIMARY KEY(hour_key, org_id, node_id))`（`hour_key` 形如 `2026-11-27T12`）
- `traffic_daily(day_key TEXT, org_id TEXT, node_id TEXT, down_bytes INTEGER, up_bytes INTEGER, PRIMARY KEY(day_key, org_id, node_id))`（`day_key` 形如 `2026-11-27`）
- `traffic_monthly(month_key TEXT, org_id TEXT, node_id TEXT, down_bytes INTEGER, up_bytes INTEGER, PRIMARY KEY(month_key, org_id, node_id))`（`month_key` 形如 `2026-11`）

## 3. 关键决策

- **写入时同步 UPSERT 多级聚合表**：每次落盘流量增量时，在同一个事务里更新细粒度表、小时表、日表和月表，并清理 48 小时前的细粒度记录。这样查询「近 30 天」或「按月（近 12 个月）」只需扫描十几到几十行汇总数据，耗时低于 1 毫秒。
- **脱敏导出采用白名单结构体**：`SanitizedExport` 仅显式拷贝自定义规则、订阅地址与常规开关字段，从类型层面杜绝把组织私钥路径或内部鉴权密钥带出。

## 4. 当前实现

- `internal/stats/schema.go`：初始化 SQLite WAL 模式并创建 `traffic_samples`、`traffic_hourly`、`traffic_daily`、`traffic_monthly` 四张表。
- `internal/stats/recorder.go`：实现 `Open`、`RecordTick`（单事务写入分钟桶、清理早于 48 小时的过期采样、同步 UPSERT 小时/日/月聚合表，并推入内存 36 点实时速率环形缓冲）与 `SeedDemoIfEmpty`。
- `internal/stats/query.go`：实现 `QueryReport`，支持 `live`、`day`、`week`、`month30`、`monthly` 五种时间粒度的上下行序列及按节点（`ByNode`）、按组织（`ByOrg`）的流量与百分比降序聚合。
- `internal/configstore/store.go`：实现 `LoadOrDefault`、`Save`（`.tmp` 临时文件写入加原子 `Rename`）以及白名单脱敏导出函数 `BuildSanitizedExport`。
- `internal/stats/stats_test.go` & `internal/configstore/store_test.go`：共 9 组单元测试全部通过 `-race` 竞态检查。

## 5. 验证方式

在 `cicd mac` 执行：
```bash
go test -v -race ./internal/stats/... ./internal/configstore/...
```
验收断言：
1. 注入跨 60 小时的模拟流量采样后，`traffic_samples` 中早于 48 小时的记录被自动清除，而 `traffic_daily` 与 `traffic_monthly` 的总字节数一分不少。
2. 查询 `day`、`week`、`month30`、`monthly` 返回的组织占比之和与节点流量总和严格等于周期总流量。
3. 导出脱敏配置 JSON 中不包含任何 `StateDir`、`AuthKey` 或令牌字符串。
