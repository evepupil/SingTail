# 模块设计：分流规则与规则集引擎

## 1. 职责与边界

- **负责的事**：
  1. 维护有序分流规则表：头部固定内置保护规则（放行 `tailscaled.exe`、`verge-mihomo.exe`、`clash-verge.exe` 直连避让，放行 `100.64.0.0/10` 与私有网段直连），中部为用户可自由增删、启停、上下调序的个人规则，尾部固定国内规则集直连与 `FINAL` 兜底规则。
  2. 解析并校验外部导入的规则文本（兼容 `TYPE,PAYLOAD,ACTION` 行格式、Clash `rules:` YAML 列表行、JSON 规则数组），批量插入用户规则区顶部。
  3. 管理 `.srs` 规则集订阅清单，下载到临时文件校验二进制魔数/非空（若存在本地 `sing-box` 可执行文件则追加 `rule-set decompile` 校验）通过后再原子覆盖目标路径。
- **不负责的事**：不直接重启 `sing-box` 进程（规则变更后通过回调通知 `internal/engine` 热重载）。

## 2. 结构与数据流

- `internal/rules/manager.go`：线程安全的规则列表 CRUD、优先级上下移动边界校验（禁止越过头部锁定区和尾部兜底区）、内置 Clash/Tailscale 直连保护规则初始化。
- `internal/rules/importer.go`：多格式规则文本解析器，支持 `DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`PROCESS-NAME`、`IP-CIDR`、`RULE-SET`，自动将 `PROXY` 归一化为 `EXIT`。
- `internal/rules/providers.go`：`.srs` 规则集元数据维护、带代理/直连回退的 HTTP 下载与临时文件安全校验替换。

## 3. 关键决策

- **头部锁定防自锁断网**：把 `tailscaled.exe` 与 `verge-mihomo.exe / clash-verge.exe` 直连规则设为头部只读锁定项，既实现与 Clash 天生无感共存不套娃，又防止用户误删导致内网或本地代理死循环。
- **先验后换防坏包**：GitHub Raw 偶发返回空包或错误页时，临时文件校验直接拦截，绝不覆盖本地已有的可用 `.srs` 文件。

## 4. 当前实现

- `internal/rules/manager.go`：两阶段无撞号初始化 `Manager`，固定头部 2 条锁定直连规则（`tailscaled.exe, verge-mihomo.exe, clash-verge.exe` 与 `100.64.0.0/10` 私有网段）和尾部 2 条锁定兜底规则（`geosite-cn, geoip-cn` 与 `FINAL`），提供并发安全的增删改排能力。
- `internal/rules/importer.go`：支持 JSON 数组、Clash YAML 列表行与 CSV 行混合解析导入，带引号感知的行尾注释剥离，自动将 `PROXY` 归一化为 `EXIT`。
- `internal/rules/providers.go`：维护 `.srs` 规则集清单并在更新时执行字节完整性校验，单条拉取失败不影响其余已成功项。
- `internal/rules/rules_test.go`：7 组单元测试（含显式 ID 防冲突、带注释引号行导入及并发测试）全部通过。

## 5. 验证方式

在 `cicd mac` 执行：
```bash
go test -v -race ./internal/rules/...
```
验收断言：
1. 新建自定义规则默认插入在头部锁定规则之后、兜底规则之前；对锁定规则执行删除或越界移动返回明确错误。
2. 混合注释、空行、Clash `- DOMAIN-SUFFIX,openai.com,PROXY` 与标准 `PROCESS-NAME,steam.exe,DIRECT` 文本导入时准确解析条数与字段。
3. 模拟远程返回损坏内容时，原有本地 `.srs` 文件保持原样不被破坏。
