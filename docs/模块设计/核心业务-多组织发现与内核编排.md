# 模块设计：多组织节点发现与内核编排控制器

## 1. 职责与边界

- **负责的事**：
  1. 多组织身份管理（`internal/tailnet`）：每个 Tailscale 组织分配独立状态目录（`data/ts-state-<orgId>`），通过 `tsnet`（及可注入接口适配器）获取登录授权 URL、同步设备状态表（筛选 `ExitNodeOption == true` 的可用出口节点，提取机器名、Tailscale IP、在线态、P2P 直连或 DERP 中继标记）与并发延迟测速。
  2. 模块化配置合成（`internal/engine/configgen.go`）：将已挂载组织端点、分流规则、本地外部代理端口（如 `127.0.0.1:7897`）、国内 `223.5.5.5` + 境外 `1.1.1.1` DoH 防污染 DNS、TUN `MTU 1280` + `ipv4_only` + 排除 `100.64.0.0/10` 拼装为完整合法的 `sing-box` 配置。
  3. 出口热切与公网 IP 核验回滚状态机（`internal/engine/controller.go`）：切换默认出口后，经本地混合代理端口探测公网 IP（`api.ipify.org` / `ifconfig.me`）；核验通过则落盘确认，核验超时或报错则立即切回原出口并生成单行回滚告警状态。
- **不负责的事**：不直接对外暴露 HTTP 路由，由 `internal/daemon` 统一封装调用。

## 2. 结构与数据流

- `internal/tailnet/provider.go`：定义 `Coordinator` 接口（含真实 `tsnet` 实现与用于无凭证开发/测试环境的沙箱实现），输出统一的组织与 `ExitNode` 列表。
- `internal/engine/configgen.go`：纯函数式配置生成器，输入 `(orgs, nodes, rules, providers, settings)` 输出标准 `sing-box` JSON 结构。
- `internal/engine/prober.go`：公网 IP 探测器接口与 HTTP 代理探测实现。
- `internal/engine/controller.go`：托管内核运行态、TUN 开关、分流模式（`rule | global | direct`）、实时连接快照读取与切换回滚状态机。

## 3. 关键决策

- **外部组件全部接口化**：将公网 IP 探测器、`sing-box` 子进程控制器与 `tsnet` 客户端抽象为 Go 接口，既能在 Windows 生产环境调真实内核，又能在 `cicd mac` 单测与无网卡预览环境里百分百复现切换成功、超时回滚、多组织挂载与实时连接采集。
- **控制连接直连**：配置生成器为私有地址和已知代理进程保留直连规则；Tailscale 控制服务器使用直连 DNS。打包内核 `sing-box 1.14.5` 包含上游 Windows 网卡绑定、流量环路和 Tailscale 重连修复。
- **启动就绪分两步**：先等本机内核管理接口响应，再通过默认 Tailscale 出口向公网发起 HTTPS 请求。首次开启分流或全局模式时，两步都成功才确认开启；直连模式不等待 Tailscale 出网。

## 4. 当前实现

- `internal/tailnet/coordinator.go` & `tsnet_auth.go`：生产模式零模拟数据启动，按组织隔离 `ts-state-<orgId>` 目录；接入官方 `tailscale.com/tsnet` 实现网页 OAuth 授权登录（`StartLogin` / `PollLogin`）、已有凭据目录导入（`ImportStateDir`）与刷新（`RefreshOrgFromTsnet`）；授权连通后自动通过用户态 `tsnet` 通道探测在线出口节点的真实公网 IP 与延迟，随后清空 `ExitNodeID` 并关闭临时实例释放目录锁交给 `sing-box` 独占。
- `internal/engine/configgen.go` & `runtime.go`：每个组织生成单 `tailscale` endpoint（补齐 `"domain_resolver": "dns-cn"` 防止解析死锁、固定 `"hostname"` 保留设备身份、`"udp_timeout": "5m"`）；虚拟网卡配置 `singtail`（`172.19.0.5/30`、`"strict_route": false`、`"stack": "mixed"`，`darwin` 目标下省略固定 `interface_name` 以适配 `utun`），本地混合端口 `127.0.0.1:17899`；路由开启 `"find_process": true` 并自动为已知出口公网 IP 添加直连绕行；托管真实 `sing-box` 子进程生命周期（35 秒握手超时、配置预检、日志落盘 `sing-box.log`、Clash API `127.0.0.1:19090` 实时采集、启动前外部同名进程冲突拦截）。
- `internal/engine/startup_probe.go`：初次启动内核时，启动和出网核验共用 35 秒等待上限。通过 Clash API 直接测试当前 Tailscale 出口，绕开用户配置的分流规则，交替探测两个公网地址。若出口不可用，停止内核并撤掉虚拟网卡。
- `internal/engine/core_command_windows.go`：在 Windows 上检查配置、读取版本和启动内核时不创建命令行窗口。桌面端直接托管与系统服务托管使用同一套启动方式，日志和错误提示仍照常保留。
- `internal/engine/prober.go` & `controller.go`：实现真实公网 IP 核验接口与 `SwitchExitAndProbe` 超时自动回滚状态机，探测成功后自动回写节点公网 IP。
- `internal/tailnet/coordinator_test.go` & `internal/engine/engine_test.go`：全部单测通过 `-race` 并发安全检查。

## 5. 验证方式

在 `cicd mac` 执行：
```bash
go test -v -race ./internal/tailnet/... ./internal/engine/...
```
验收断言：
1. 生成的 `sing-box` JSON 包含所有已授权组织的 `tailscale` endpoint、`MTU 1280`、`100.64.0.0/10` 排除段、Clash 与 Tailscale 进程直连规则以及本地外部代理 outbound。
2. 当切换目标出口探测成功时，`ActiveExitID` 更新且无告警；当目标出口探测返回超时或异常时，自动回滚回切换前的 `ActiveExitID` 并写入回滚提示。
3. 内核管理接口已经响应、出口暂未连通时，继续等待并重试；直连路径不能冒充 Tailscale 出口。内核提前退出或超时都应返回失败。
4. 安装包真机验收：保留已有授权，开启分流后分别访问国内和境外站点；换用不可用出口，确认失败时虚拟网卡撤掉且系统恢复联网。
5. Windows 子进程回归测试：用相同的启动方式运行命令行程序，检查子进程没有分配控制台。
