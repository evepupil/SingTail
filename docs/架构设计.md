# SingTail 架构设计

## 1. 总体架构图

**框图编号说明**：
1. **桌面前端界面**：负责五大业务视图、多粒度流量 Canvas 绘制、弹窗表单与 `Ctrl+K` 命令面板，运行在普通用户权限下。
2. **Windows 系统托盘模块**：常驻右下角托盘图标，提供关窗口后台保留与快捷开关、秒切出口能力。
3. **本地控制网关**：监听 `127.0.0.1` 回环地址并校验本机随机生成的访问令牌（防浏览器恶意网页跨站调用），向桌面端提供统一查询与控制接口。
4. **多组织节点发现**：按组织分目录运行官方 `tsnet` 状态机，拉取授权链接并自动枚举该组织内所有开启了出口权限的节点、延迟与直连/中继状态。
5. **规则与规则集管理**：维护自定义分流规则顺序、解析导入本地规则文件、拉取并校验 `.srs` 二进制规则集。
6. **流量采样与历史统计库**：定时从内核采集各连接与出口收发增量，写入本地 `SQLite` 单文件库，自动清理超过 48 小时的细粒度采样并滚动合并到按小时、按日、按月及按组织/节点的汇总表。
7. **内核编排与回滚控制器**：把组织出口、规则和防污染参数拼装成标准 `sing-box` 配置并托管进程；切换出口后实测公网 IP，异常时立即回滚至上一健康出口。
8. **官方 sing-box 内核**：建立系统虚拟网卡接管流量，内置直连放行 `tailscaled.exe` 与 `verge-mihomo.exe` / `clash-verge.exe`，实现与外部客户端无感共存。

## 2. 架构分层表

| 分层 | 对应代码目录 | 包含模块 | 职责 | 允许依赖谁 |
|---|---|---|---|---|
| 契约层 | `internal/contract`<br>`frontend/src/types` | 共享模型与接口定义 | 定义组织、出口节点、规则、连接、流量聚合响应等统一数据结构 | 仅标准库 |
| 数据存储层 | `internal/stats`<br>`internal/configstore` | 流量统计库、脱敏配置库 | SQLite 流量落盘与滚动聚合查询、本地 JSON 配置读写与脱敏导出 | 契约层 |
| 核心业务层 | `internal/rules`<br>`internal/tailnet`<br>`internal/engine` | 规则引擎、多组织节点发现、内核编排与回滚 | 规则解析校验、多组织出口同步、`sing-box` 配置生成与切换验 IP 回滚 | 契约层、数据存储层 |
| 系统接入层 | `internal/daemon`<br>`internal/syswin`<br>`cmd/singtail-service` | 本地控制网关、Windows 服务与进程工具 | 暴露本机控制 API、注册 Windows 系统服务、枚举本机运行中进程 | 核心业务层、数据存储层、契约层 |
| 桌面前端与外壳层 | `frontend/`<br>`cmd/singtail-desktop`<br>`.github/workflows/` | 桌面界面、Wails 外壳与托盘、打包流水线 | 渲染低圆角界面、响应用户交互、驻留系统托盘、产出绿色包与安装包 | 通过本地控制 API 调系统接入层 |

## 3. 核心主流程

### 3.1 切换出口并核验回滚流程

```text
[用户点击新出口 B]
       │
       ▼
[3 控制网关] 记录原出口 A，状态置为「核验中 (verifying)」
       │
       ▼
[7 内核编排器] 热切 selector 默认出口至 B
       │
       ▼
[7 内核编排器] 经本地混合代理端口并发探测双公网 IP 接口 (超时 6s)
       ├── 命中预期公网 IP / 连通成功 ──► 更新当前生效出口为 B，清除告警，写入配置缓存
       │
       └── 超时或连通失败 ─────────────► 立即将 selector 切回原出口 A，返回回滚原因横幅
```

### 3.2 流量采样与多粒度滚动归档流程

```text
[每 1 秒定时采样] ──► 读取内核连接快照，算出本秒各出口节点上下行增量字节
       │
       ├──► 推入内存 36 秒环形队列 ──► 驱动前端「实时」速率波形
       │
       └──► 累加至内存分钟桶（每 60 秒或退出前刷入 SQLite）
                │
                ├── 写入 traffic_samples（细粒度表，自动删除 >48h 旧行）
                └── UPSERT 累加至 traffic_hourly / traffic_daily / traffic_monthly（带 org_id + node_id）
```

## 4. 关键状态流转（引擎与出口状态机）

```text
[STOPPED 已关闭] ──(开启 TUN)──► [RUNNING 正常运行 (出口 A)]
       ▲                               │
   (关闭 TUN)                     (点击切换出口 B)
       │                               ▼
       │                      [VERIFYING 核验出口 B]
       │                         ├── 核验通过 ──► [RUNNING 正常运行 (出口 B)]
       └─────────────────────────┴── 核验失败 ──► [RUNNING 已回滚原出口 A + 回滚横幅]
```

## 5. 故障隔离与重启恢复

- **新组织授权隔离**：挂载新 Tailscale 组织时，在独立端口（如 `127.0.0.1:17899`）和独立凭据目录拉起临时实例，绝不触碰当前正在跑流量的正式虚拟网卡；哪怕中途放弃登录，现有网络零中断。
- **坏规则集隔离**：更新 `.srs` 规则集先下载到系统临时目录，校验文件头与反编译无误后才原子替换正式文件；任何一步失败均保留旧文件不动。
- **守护进程崩溃与重启恢复**：Windows 服务配置崩溃 1 分钟内自动重启；启动时从 `configstore` 读取上次核验通过的出口、分流模式和规则，从 `SQLite` 恢复全部历史流量账本，状态无缝衔接。
- **干净退出保障**：服务停止时主动关闭 `sing-box` 子进程释放虚拟网卡，全程不修改 Windows 注册表系统代理项，杜绝关软件后整机断网。

## 6. 扩展点设计

| 以后要加什么 | 改哪里 |
|---|---|
| 支持 Headscale 自建控制服务器登录 | 仅在 `internal/tailnet` 的组织配置里增加 `ControlURL` 字段传给 `tsnet.Server`，其余模块零改动 |
| 新增 macOS / Linux 桌面端支持 | 新增 `internal/sysdarwin` / `internal/syslinux` 实现系统服务与进程枚举接口，前端与核心业务层原样复用 |
| 支持更多外部规则格式（如 QuantumultX） | 在 `internal/rules/importer.go` 注册新的行解析函数即可 |
