# SingTail 技术设计

## 1. 技术选型

- **Go 1.23+（Google 的高性能编译型语言，编译产物为独立单文件）**：编写后台核心守护服务、桌面桥接层与系统托盘控制；选用理由是 Tailscale 官方库与 `sing-box` 均为 Go 语言生态，同语言集成零摩擦，且开启纯 Go 模式（`CGO_ENABLED=0`）可在 `cicd mac` 上秒级交叉编译出 Windows `.exe`；备选是 Rust（需跨语言拼装节点发现，维护成本翻倍）。
- **Wails v2（Go 语言轻量桌面框架，复用 Windows 10/11 内置 WebView2 渲染前端）**：打包无边框桌面客户端；选用理由是不捆绑百兆浏览器内核（体积十余兆、省内存），原生支持 `CGO_ENABLED=0` 构建 Windows 目标，且自带 NSIS 安装包构建支持；备选是 Electron（体积与内存过重）。
- **tailscale.com/tsnet（Tailscale 官方内嵌虚拟组网库）**：管理多组织独立登录态、获取网页授权链接并轮询授权完成状态、导入已有 `ts-state` 凭据目录、移除组织凭据、自动发现组织内开启了出口权限（Exit Node）的节点及在线/直连状态；选用理由是支持单机多目录并存多个组织身份；备选是调用外部 `tailscale.exe`（仅支持单组织且影响宿主原客户端）。
- **sing-box 官方内核（通用代理与虚拟网卡分流引擎）**：承担 TUN 虚拟网卡接管、国内外分流 DNS、规则与 `.srs` 规则集匹配；选用理由是实测网络延迟与防污染表现极稳，由守护服务自动生成配置并托管进程；备选是 Mihomo。
- **React 19 + TypeScript 5 + Vite 6（组件化前端框架 + 严格类型检查 + 极速构建器）**：实现桌面端五大视图、多粒度流量 Canvas 图表与交互弹窗；选用理由是复杂状态可维护性强，`cicd mac` 已有现成 Node 24 与 pnpm 环境；备选是手写原生 DOM。
- **原生 CSS 变量设计系统（复用原型 `tokens.css` 与 `desktop.css`）**：落地 `0px/2px` 低圆角、`1px` 细线网格与明暗双主题；选用理由是零运行时开销、像素级还原已确认原型；备选是第三方组件库。
- **SQLite（`modernc.org/sqlite`，纯 Go 实现的单文件嵌入式数据库）**：存储流量历史与组织/节点分布账本（保留近 48 小时细粒度采样，历史数据自动滚动聚合为按小时、按日、按月汇总，常年保持几 MB 小体积）；选用理由是免外部服务、纯 Go 免 C 编译器；备选是本地 JSON 文件。
- **Vitest + Go testing（前后端轻量单元测试框架）**：覆盖核心业务逻辑单测；选用理由是零冗余配置、执行极快。
- **GitHub Actions + NSIS + hdiutil（云端自动化构建流水线 + 双平台打包工具）**：推送版本标签（`v*`）时分别在 `windows-latest` 与 `macos-latest` 自动拉取 `sing-box 1.14.3` 内核与 7 个官方 `.srs` 规则包并内置打包，最终由 `publish-release` 汇总上传四份 Release 产物——Windows 绿色便携包（`SingTail-windows-amd64-portable.zip`）、Windows 安装向导包（`SingTail-windows-amd64-setup.exe`）、macOS Apple Silicon 镜像（`SingTail-macos-arm64.dmg`）与 macOS Intel 镜像（`SingTail-macos-amd64.dmg`），并附带 `SHA256SUMS.txt`；选用理由是跨平台用户下载即用，零手动配置内核与规则文件。

## 3. 工程规范

- **严格编译模式**：
  - TypeScript 开启 `"strict": true`、`"noUncheckedIndexedAccess": true`、`"noImplicitOverride": true`、`"noUnusedLocals": true`。
  - Go 开启 `gofmt` 格式校验、`go vet` 静态分析与纯 Go 编译检查（`GOOS=windows GOARCH=amd64 CGO_ENABLED=0`）。
- **一键远程门禁（`cicd mac` 执行）**：
  - 在 `golfjoy@192.168.0.68:~/remote-work/SingTail` 上运行 `bash scripts/remote-gate.sh`，一次性完成：Go 格式与静态检查、Go 全量核心单测、Windows 双可执行文件交叉编译、前端 TypeScript 严格检查、前端 Vitest 单测与前端生产构建。
- **换行符规范**：`.gitattributes` 锁定全仓默认 `eol=lf`，`*.ps1` / `*.bat` / `*.cmd` / `*.nsi` 固定 `eol=crlf`。

## 4. 测试策略

- **编写单测的核心逻辑**：
  - `internal/stats`：流量写入、48 小时细粒度滚动清理、按今日/近 7 天/近 30 天/按月趋势聚合、按组织与出口节点占比统计。
  - `internal/rules`：规则增删改排、内置保护规则不可删校验、外部规则文件多格式解析导入、规则集校验。
  - `internal/engine`：模块化 `sing-box` JSON 配置合成（验证 `tailscaled.exe` / `verge-mihomo.exe` 直连避让、`8.128.0.0/10` 规则、本地代理转发出口）、出口切换公网 IP 核验与超时自动回滚状态机。
  - `internal/configstore`：配置读写与脱敏导出（断言私密目录与令牌字段被彻底剔除）。
  - `frontend/src/state`：前端流量单位换算、占比计算与规则/连接过滤纯函数。
- **不写单测的范围**：纯界面布局与样式、路由装配胶水、常量定义；界面统一通过浏览器真实渲染截图与交互探针验收。

## 5. 关键决策

1. **双进程权限隔离**：`singtail-service.exe` 以系统服务身份管虚拟网卡，`singtail.exe` 以普通桌面用户身份渲染界面和托盘，彻底消除日常打开软件的 UAC 弹窗。
2. **近期细粒度 + 远期滚动汇总的轻量流量库**：SQLite 仅保留最近 48 小时分钟级明细，自动向上归并到按小时、按日、按月聚合表，兼顾「今日 / 近 7 天 / 近 30 天 / 按月」多粒度秒查与几 MB 的极小磁盘占用。
3. **GitHub Actions 双平台内置内核打包**：打 Tag 时自动并行构建 Windows（`.zip` + `-setup.exe`）与 macOS（`arm64.dmg` + `amd64.dmg`），统一内置 `sing-box 1.14.3` 与 7 个基础 `.srs` 规则包后发布至 GitHub Releases。
4. **前端 API 层支持「桌面壳 + 浏览器预览」双通道**：在 Windows 上直接走本地守护服务真实接口，在 `cicd mac` 无虚拟网卡预览环境下也能通过守护服务的模拟适配器完整联调验收所有界面交互。
